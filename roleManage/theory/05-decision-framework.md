# 05 · 决策框架：如何选出模型组合

> 前置：01、02、models（至少 RBAC/ABAC/08）、04。  
> 本章输出进入 O2 决策句式与档位；填空见 [06](./06-outputs.md)。

## 1. 学习目标

读完本章，你应能：

1. 按 Q1→Q4 顺序决策，而不是凭「感觉选高级模型」  
2. 在 S / M / L 三档中定位项目并说明理由  
3. 写出完整**决策句式**（可给业务方听懂）  
4. 用反例识别「跳步选型」  

## 2. 决策在理解链上的位置

```
问题已定义（01）
  → 需求落在演进哪一段（02）
  → 模型能力已懂（models）
  → 项目约束已问清（04）
  → 本决策章：选出组合与档位
  → 06：写成交付物
```

决策不是投票「哪个模型更酷」，而是：**用最小足够的模型组合，覆盖已澄清的约束。**

## 3. 决策树（必须按序）

### Q1. 主要是岗位能力，还是对象归属 / 分享？

| 信号 | 倾向 |
|------|------|
| 后台、ERP、运营、内部工具，按岗授权 | **RBAC** 为主 |
| 大量「把某资源分享给某人/某组」 | **RBAC + ACL**（或嵌套深则 **ReBAC**） |
| 密级强制隔离是硬需求 | 引入 **MAC** 思想（标签 + 强制策略） |

**理解：** Q1 决定「主叙事」是岗位还是对象。多数企业内部系统答案是岗位 → RBAC。

### Q2. 权限是否强烈依赖属性 / 环境？

| 信号 | 倾向 |
|------|------|
| 几种固定岗位即可 | **纯 RBAC**（偏 S） |
| 本部门 / 本人 / 租户隔离 / 简单时间窗 | **RBAC + 数据范围规则**（轻量 ABAC，偏 M） |
| 规则极多、跨服务统一、需策略外置与可测 | **完整 ABAC / 策略引擎**（偏 L，贵） |

**理解：** 「本部门」不等于必须上策略引擎；轻量规则通常够用。

### Q3. 只要「进门判定」，还是「使用过程仍要管」？

| 信号 | 倾向 |
|------|------|
| 请求级鉴权即可 | 传统访问控制足够 |
| 会话中吊销、额度用完断开、必须先尽义务且可中止 | 引入 **UCON** 思维（局部机制或平台） |

**理解：** 导出前弹窗同意，常常是产品流程，不必宣称「我们做了 UCON」。

### Q4. 粒度停在哪？

```
模块 → 菜单/功能 → 操作 → 字段 → 行/对象
                       ▲ 首期默认
```

更细必须有业务驱动 + 治理预算。Q4 的答案直接写入 O7。

## 4. 三档位精讲

### 档位 S · 简单后台

| 项 | 内容 |
|----|------|
| 画像 | 岗位少（≤5）、无复杂部门隔离、无对象分享 |
| 模型 | **纯 RBAC** |
| 功能 | 操作级权限码 |
| 数据 | 全量 **或** 仅 SELF，二选一 |
| 不做 | ACL、字段级、完整 ABAC、UCON |
| 风险 | 日后突然要「本部门」→ 升级 M，需改 O6 |

**范例方向：** 见 [cases/s-tier-simple-admin.md](./cases/s-tier-simple-admin.md)

### 档位 M · 标准企业应用（最常见）

| 项 | 内容 |
|----|------|
| 画像 | 清晰岗位 + 部门/本人范围；偶发实例分享 |
| 模型 | **RBAC + 数据范围规则**；必要时 **白名单 ACL** |
| 功能 | 角色可配置权限码 |
| 数据 | SELF / DEPT / DEPT_AND_CHILD / ALL 等，语义写死 |
| 不做 | 完整策略引擎、ongoing UCON、全站 ACL 化 |
| 范例 | [cases/m-tier-order-ops.md](./cases/m-tier-order-ops.md) |

### 档位 L · 复杂协作 / 多租户平台

| 项 | 内容 |
|----|------|
| 画像 | 多租户硬隔离、复杂属性条件、深层协作关系 |
| 模型 | **RBAC + ABAC（或强规则）+（可选）ReBAC/ACL** |
| 治理 | 策略测试、拒绝原因、属性源质量必须有人负责 |
| 按需 | UCON（计量、吊销、义务） |
| 范例 | [cases/l-tier-multitenant-collab.md](./cases/l-tier-multitenant-collab.md) |

**升级纪律：** S→M→L 只能因**信号**升级（写入 O9），不能因「想做强」升级。

## 5. 决策句式（必须会写）

模板：

> 本项目以 **\_\_\_** 为主模型；  
> 因 **\_\_\_**（业务信号），补充 **\_\_\_**；  
> 功能权限粒度到 **\_\_\_**；数据权限采用 **\_\_\_**；  
> 首期明确不做 **\_\_\_**。  
> 对照演进线：……  

示例（M）：

> 本项目以 **RBAC** 为主模型；  
> 因存在部门数据隔离，补充 **本部门/本人范围规则（轻量 ABAC）**；  
> 因个别工单需临时协作，补充 **ticket 对象级 ACL**；  
> 功能权限粒度到 **操作级**；数据权限采用 **SELF/DEPT/DEPT_AND_CHILD/ALL**；  
> 首期明确不做 **字段级、完整 ABAC 引擎、UCON ongoing**。  
> 对照演进线：需求主要落在 RBAC，局部触及 ABAC 思想与 ACL 旁支。  

## 6. 跳步选型反例

| 错误 | 为何错 | 应如何 |
|------|--------|--------|
| 先定「上 ABAC 引擎」再补需求 | 倒置 | 先 Q1–Q4 与 04 清单 |
| 有分享就上 ReBAC | 可能过度 | 对象少、无深层继承 → ACL 往往够 |
| 有租户字段就自称 MAC | 概念错 | 租户隔离 ≠ 密级强制 |
| 最新模型 = 更好 | 错 | 匹配问题与治理能力 |

## 7. 小结与自测

### 小结

按 Q1–Q4 决策 → 落入 S/M/L → 写决策句式 → 进 06 填交付物。  
最小足够原则：能静态不动态，能规则不引擎，能 ACL 不先上 ReBAC。

### 自测

1. 只存在「管理员 / 普通用户」、数据全可见：档位？句式？  
2. 岗位清晰 + 本部门 + 无分享：为何是 M 不是 L？  
3. Q3 答「要会话中吊销」但 Q1/Q2 仍很简单：模型组合怎么写才不夸张？  
4. 不看案例，用四句话描述 S/M/L 差异。
