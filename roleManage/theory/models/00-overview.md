# 00 · 模型总览：地图、主线与学法

## 1. 学习目标

- 能画出 DAC→MAC→RBAC→ABAC→UCON 主线，并指出 ACL、ReBAC 的旁支位置  
- 能用一句话说清每个模型「判定主要看什么」  
- 能解释：演进线是能力叙事，不是实施顺序，也不是淘汰顺序  

## 2. 一张地图

```
安全经典线：  DAC ⇄ MAC
企业管理线：       → RBAC →（常与 ABAC 混合）
动态细粒度：            → ABAC
使用全过程：                  → UCON
对象侧名单：  ACL（常作为 DAC 的实现形态，也可挂在 RBAC 之上）
关系授权：    ReBAC（与 ABAC 同期偏应用的另一条路）
```

## 3. 主线在解决什么（预习用）

| 模型 | 一句话 | 主要看什么 |
|------|--------|------------|
| DAC | 主人说了算 | 所有者如何授权 |
| MAC | 系统强制 | 安全标签 / 强制策略 |
| RBAC | 按角色打包权限 | 用户是否拥有含该权限的角色 |
| ABAC | 按属性与策略 | 属性是否满足策略 |
| UCON | 管使用全过程 | 授权 + 义务 + 条件（可持续、可变） |
| ACL | 资源上的名单 | 该客体允许谁做什么 |
| ReBAC | 关系是否成立 | 图上的关系能否推出授权 |

## 4. 如何学本目录（教材建议）

1. **先读演进**：[../02-model-evolution.md](../02-model-evolution.md)（30 分钟级）  
2. **再按主线精读** 01→05，每章做自测  
3. **补旁支** 06、07（很多业务需求其实落在这里）  
4. **用 08 收束**，尝试默写「本项目模型组合」决策句式  
5. 回到 [../05-decision-framework.md](../05-decision-framework.md) 做一次虚构立项练习  

## 5. 贯穿全书的三条纪律

1. **功能权限与数据权限分开谈**——模型可以组合，概念不要混。  
2. **角色 ≠ 部门**——角色是权限包；部门常是数据范围属性。  
3. **能静态绑定就先静态**——ABAC/UCON 是能力上限，不是默认档位。
