# 术语表（Glossary）

全书统一用语。按主题分组；英文缩写首次出现处给出全称。  
与模型专章对照：[models/README.md](./models/README.md)

---

## A. 问题框架（四元组）

| 术语 | 英文 | 定义 |
|------|------|------|
| **主体** | Subject | 发起访问请求的一方：人、服务账号、外部应用等 |
| **客体** | Object | 被访问的目标：菜单、API、业务记录、文件等 |
| **操作** | Action | 对客体执行的动作：查看、创建、修改、删除、导出、审批等 |
| **环境** | Context / Environment | 访问发生时的上下文：时间、IP、租户、设备、风险分等 |
| **访问矩阵** | Access Matrix | 抽象模型：行=主体，列=客体，单元格=允许的操作集合 |
| **授权** | Authorization | 判定是否允许访问（区别于认证 Authentication） |
| **认证** | Authentication | 证明「你是谁」；授权是「你能做什么」 |
| **鉴权** | — | 口语统称，常混指认证+授权；教材中尽量分开写 |
| **默认拒绝** | Default Deny | 未显式允许则拒绝；最小权限原则的操作化 |
| **最小权限** | Least Privilege | 只授予完成任务所必需的最小能力 |

---

## B. 权限分层（全书纪律）

| 术语 | 定义 |
|------|------|
| **功能权限** | 能否使用某能力：菜单、按钮、接口、操作码 |
| **数据权限** | 能作用到哪些数据行/实例：本人、本部门、租户、全量等 |
| **操作级粒度** | 权限切到「资源:操作」（如 `order:export`），推荐首期默认 |
| **字段级权限** | 同一记录上，不同字段可见/可改不同；成本高，慎选 |
| **对象级 / 实例级** | 针对单条业务记录或单个文件的授权（常走 ACL/ReBAC） |
| **权限码** | 权限的稳定符号名，如 `order:view`；鉴权真源，非菜单 ID |
| **数据范围** | 在已有功能权限下，进一步限制可见数据集合的规则语义 |

## C. 访问控制模型（主线）

| 术语 | 英文 | 一句话 |
|------|------|--------|
| **DAC** | Discretionary Access Control | 客体属主自主决定谁可访问 |
| **MAC** | Mandatory Access Control | 系统按安全标签/策略强制判定，属主不能随意推翻 |
| **RBAC** | Role-Based Access Control | 用户通过角色获得权限包 |
| **ABAC** | Attribute-Based Access Control | 由主体/资源/操作/环境属性 + 策略动态判定 |
| **UCON** | Usage Control | 使用控制：授权+义务+条件，可持续、属性可变 |
| **ACL** | Access Control List | 客体上的「谁可做什么」名单（旁支） |
| **ReBAC** | Relationship-Based Access Control | 由关系图路径是否成立判定（旁支） |
| **Capability** | — | 主体持有的能力票证（访问矩阵「行」视角，常与 DAC 同论） |

### UCON · ABC

| 术语 | 含义 |
|------|------|
| **Authorization（A）** | 是否允许 |
| **oBligation（B）** | 必须履行的义务（同意、审计、通知等） |
| **Condition（C）** | 环境须满足的条件 |
| **pre** | 使用开始前的判定 |
| **ongoing** | 使用过程中的持续判定 |
| **post** | 与使用后义务相关的判定 |
| **可变性** | Mutability：属性可在使用中更新并影响后续判定 |

### MAC 相关

| 术语 | 含义 |
|------|------|
| **安全标签 / 密级** | 主体与客体上的安全等级或类别 |
| **MLS** | Multi-Level Security，多级安全 |
| **不上读 / 不下写** | 经典机密性直觉：高密级不读低密级、高密级不写低密级（表述因模型而异） |

## D. RBAC 专用

| 术语 | 英文 | 定义 |
|------|------|------|
| **用户** | User | 被指派角色的主体 |
| **角色** | Role | 权限的命名集合，对应职责/岗位 |
| **权限** | Permission | 对客体执行某操作的许可 |
| **用户—角色指派** | UA (User Assignment) | 用户与角色的绑定关系 |
| **角色—权限指派** | PA (Permission Assignment) | 角色与权限的绑定关系 |
| **角色继承** | Role Hierarchy | 子角色自动拥有父角色权限 |
| **会话 / 激活角色** | Session / Active Roles | 用户登录后实际启用的角色子集（理论模型） |
| **RBAC96** | — | Sandhu 等提出的 RBAC 模型家族，教材常用参照 |
| **角色爆炸** | Role Explosion | 为覆盖组合条件而角色数量失控 |
| **职责分离** | SoD, Separation of Duties | 互斥职责不得由同人承担（如制单与审核） |
| **互斥角色** | Mutually Exclusive Roles | SoD 的一种：两角色不能同时赋给同一用户 |
| **基数约束** | Cardinality Constraint | 如某角色最多 N 人、某用户最多 M 角色 |

## E. ABAC 与策略

| 术语 | 定义 |
|------|------|
| **属性** | 描述主体、资源、操作或环境的特征值 |
| **策略** | Policy：规则集合，对属性求值得到 permit/deny |
| **策略决策点** | PDP | Policy Decision Point：做判定 |
| **策略执行点** | PEP | Policy Enforcement Point：执行判定结果 |
| **轻量属性规则** | — | 工程常见：RBAC + 部门/本人过滤器，共享 ABAC 思想但不上完整引擎 |
| **完整 ABAC / 策略引擎** | — | 策略外置、可组合、需专门治理与测试 |
| **PBAC** | Policy-Based Access Control | 与 ABAC 高度重叠，常混用 |
| **XACML** | — | 策略语言标准之一（了解即可） |
| **拒绝原因可解释** | — | 策略系统应能说明为何拒绝；ABAC 治理难点之一 |

## F. ACL 与 ReBAC

| 术语 | 定义 |
|------|------|
| **ACE** | Access Control Entry：ACL 中的一条（主体+权限+允许/拒绝） |
| **属主** | Owner | 对客体有支配性授权权的主体（DAC/ACL 语境） |
| **转授** | Delegation / Grant Propagation | 被授权者是否可继续授权他人 |
| **权限扩散** | Permission Propagation | 授权沿链传播导致不可控扩散（DAC 风险） |
| **关系元组** | Relation Tuple | ReBAC：如 `(文档, parent, 文件夹)` |
| **关系推导 / 可达** | — | 沿关系图按配置规则推出是否具备某关系 |
| **Zanzibar** | — | Google 关系授权系统的著名工业实现 |

## G. 组织与多租户

| 术语 | 定义 |
|------|------|
| **租户** | Tenant | 多租户 SaaS 中的隔离边界；常作为一等属性或硬分区 |
| **部门** | Department | 组织归属；常作为**数据范围**来源，≠ 角色 |
| **用户组** | Group | 人的集合；可用于 ACL 或间接指派，≠ 角色（概念上） |
| **组织树** | Org Tree | 部门层级；影响「本部门是否含下级」等语义 |
| **数据归属** | Data Ownership | 记录上的负责人、创建者、所属部门等字段 |

## G2. 数据范围常用语义

| 范围名 | 语义（须在 O6 中写清细节） |
|--------|---------------------------|
| **SELF** | 仅本人创建或负责的数据 |
| **DEPT** | 本部门；是否含下级部门须明确定义 |
| **DEPT_AND_CHILD** | 本部门及下级部门 |
| **TENANT** | 本租户内全部（多租户场景） |
| **ALL** | 跨部门/系统全量；慎用，常仅管理员 |
| **CUSTOM** | 自定义规则（如指定项目列表） |

|------|------|

## I. 易混辨析（速查）

| 易混对 | 区分 |
|--------|------|
| 认证 vs 授权 | 身份 vs 能力 |
| 角色 vs 部门 | 权限包 vs 组织归属/数据范围 |
| 角色 vs 用户组 | 职责权限包 vs 人的集合 |
| 权限码 vs 菜单 | 鉴权真源 vs UI 展现 |
| DAC vs ACL | 策略类别 vs 常见数据结构 |
| RBAC vs ABAC | 静态角色绑定 vs 属性策略动态判定 |
| ABAC vs 代码 if | 可治理策略 vs 散落分支 |
| ACL vs ReBAC | 枚举谁 vs 关系推导谁 |
| ABAC vs UCON | 属性策略 vs 使用全过程（义务/持续/可变） |
| 租户隔离 vs MAC | 分区/属性条件 vs 强制密级标签体系 |
| 演进线 vs 实施顺序 | 能力叙事 vs 工程起步通常从 RBAC |
