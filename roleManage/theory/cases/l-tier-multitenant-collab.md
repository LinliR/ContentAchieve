## 0. 业务背景

**澄协（ChengCollab）**：SaaS 文档协作。

- **多租户**：租户间强隔离（硬边界）  
- 租户内：团队、文件夹、文档嵌套；**成员关系**决定默认可读/可编  
- 全局功能：租户管理员可管成员与计费页；普通成员按关系访问文档  
- 另有：外部分享链接（可选）、工作时间外禁止导出（属性条件）  
- 计量：单租户导出次数日限额（触及 UCON **思维**，首期用配额计数近似，不上完整 UCON 平台）  

**决策树：** Q1 岗位+大量关系分享 → RBAC + ReBAC；Q2 租户+时间等属性 → ABAC 规则；Q3 配额近似 ongoing；Q4 操作级+实例关系 → **档位 L**。

---

## O1 · 问题框架

- Subject：租户内用户；租户管理员；平台超级管理员（极少）；服务账号（Webhook）  
- Object：**功能**（计费、成员管理）+ **实例**（folder/doc）  
- Action：view / edit / share / export / admin_billing / admin_member  
- Context：tenant_id（硬边界）、时间（导出）、配额剩余  
- 功能权限：要（平台/租户管理类）  
- 数据权限：要 = **租户隔离** + **关系推导可见性** + 少量属性条件  

## O2 · 模型选型

- 主模型：RBAC（管租户级/平台级功能）  
- 旁支/组合：  
  - **租户硬隔离**（先于一切）  
  - **ReBAC**（团队成员、文件夹父子 → 文档权限）  
  - **ABAC 规则**（如 `action==export AND is_workday`）  
  - 配额：可变计数（UCON 思维局部）  
- 档位：L  
- 决策句式：

> 本项目以 **RBAC** 管理租户/平台功能权限；因多租户强隔离与深层文档成员关系，补充 **租户边界 + ReBAC**；因导出受工作日与配额约束，补充 **属性规则与配额计数（轻量 UCON 思维）**；功能粒度 **操作级**；文档可见性以 **关系推导** 为主。首期不做 **全站 MAC、完整 UCON 中间件、字段级**。对照演进线：超出纯 RBAC，进入 ABAC/ReBAC 能力区，局部触及 UCON。  

## O3 · 关键考量结论（摘录）

| 编号 | 结论 |
|------|------|
| A1 | 租户内岗位偏少（admin/member），复杂在关系不在角色数量 |
| A3 | 多租户硬隔离；跨租户默认不可能 |
| B2 | 租户边界 + 关系可见性 + 导出条件 |
| B4 | 核心是关系分享/继承，故 ReBAC 优先于大面积 ACL |
| C1–C2 | RBAC + ReBAC + 属性规则 |
| C3 | 配额用计数近似；真正 ongoing 播放类不做 |
| D5 | 拒绝原因：至少能区分「无功能权 / 非本租户 / 无关系 / 非工作日 / 配额用尽」 |
| F | 见 O7 |

## O4 · 权限对象清单（逻辑·摘录）

| 资源 | 操作 | 权限码 | 备注 |
|------|------|--------|------|
| billing | 查看/管理 | tenant:billing | 仅 tenant_admin |
| member | 管理 | tenant:member_admin | |
| doc | 查看/编辑/分享/导出 | 由 ReBAC 关系蕴含；export 另加属性条件 | 不把每篇文档做成角色 |
| platform | 超级管理 | platform:super | 平台方 |

## O5 · 角色初稿（功能层）

| 角色 | 职责 | 权限包 | 说明 |
|------|------|--------|------|
| tenant_admin | 租户管理 | tenant:\* | 不自动拥有所有文档 edit（仍看关系或显式拥有） |
| tenant_member | 普通成员 | （功能上可进应用） | 文档权几乎全由 ReBAC |
| platform_super | 平台运维 | platform:super | 严格审计；默认不进租户内容 |

文档上的 viewer/editor/owner 是**关系名**，不要做成全局 RBAC 角色爆炸。

## O6 · 数据范围 / 可见性规则

| 层 | 规则 |
|----|------|
| L0 租户 | `resource.tenant_id == subject.tenant_id`；失败则拒绝（对平台超管另策） |
| L1 关系 | ReBAC：member/owner/parent 等配置推导 view/edit |
| L2 属性 | export 额外：`is_workday AND quota.remaining > 0` |
| 组合 | L0 ∧ (L1 关系成立) ∧ (若 export 则 L2) |

**歧义消除：** 文件夹 viewer 是否继承到子文档 → **是**（写入 ReBAC 配置，O9 变更需评审）。

## O7 · 首期做 / 不做

- 做：租户隔离；RBAC 功能角色；ReBAC 文档授权；导出工作日+配额；拒绝原因分类；关系变更审计  
- 不做：字段级；完整 UCON 平台；密级 MAC；跨租户协作；把文档权做成全局角色表  

## O8 · 风险与开放问题

| 问题 | 影响 | 计划何时定 |
|------|------|------------|
| 外部分享链接主体如何建模 | 匿名 Subject | 分享功能立项时 |
| 关系配置复杂度导致误授权 | 安全事故 | 上线前做关系规则测试集 |
| 配额是否要 ongoing 中断已开始的导出流 | 体验/安全 | 二期 |

## O9 · 演进预留

- 关系规则持续膨胀、难解释 → 加强测试与「证明路径」展示，仍先不换模型  
- 出现法定密级 → 评估局部 MAC  
- 出现长连接内容流强制中途停权 → 评估 UCON ongoing 机制  
- 出现跨租户联邦 → 单独架构项，不在首期权限模型内偷偷加  

## 与 M 档差异（帮助理解）

| 点 | M 澄单 | L 澄协 |
|----|--------|--------|
| 隔离 | 单租户部门 | 多租户硬边界 |
| 实例权 | 少量 ticket ACL | 系统性 ReBAC |
| 属性 | 部门范围为主 | 时间+配额等更多条件 |
| 治理 | 中 | 必须可解释与策略/关系测试 |

## 验收

O1–O7 完整；O6 分层清晰；句式可讲解；治理要求写明 → **理论阶段可通过（L），工程复杂度显著高于 M**。
