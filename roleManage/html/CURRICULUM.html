学习路线（Curriculum）

本文件告诉你：按什么顺序读、每站学什么、如何检验自己真的懂了。
目标不是「看过文档」，而是能独立完成一份理论立项（O1–O9）。

直接按本目录 Markdown 阅读即可。

1. 全景地图

第 0 周：词汇
  glossary.md

第 1 阶段：问题与演进（方法论上半）
  01 问题框架 → 02 演进逻辑

第 2 阶段：模型教材（理论核）
  models/00 → 主线 01…05 → 旁支 06…07 → 08 对照

第 3 阶段：立项方法（方法论下半）
  04 考量 → 05 决策 → 06 输出

第 4 阶段：对照练习
  cases/（先自己填空白，再看范例）

03-models.md 只是模型目录入口，不占用学时。

2. 推荐日程（可压缩可拉长）

日序 内容 产出（强制）
D1 glossary.md 通读 + 01 自测 1–5；用四元组写 2 个真实场景
D2 02 默写缺口传递；标出旁支位置
D3–D5 models/ DAC→RBAC 每章自测；RBAC 章画用户-角色-权限图
D6–D7 ABAC、UCON + ACL、ReBAC 对比表：ABAC vs ReBAC；UCON ABC 拆一个例子
D8 models/08-comparison.md 默写对照表 + 组合口诀
D9 04 + 05 对虚构项目走完 Q1–Q4，选定 S/M/L
D10 06 空白填写 独立完成 O1–O9（不看案例）
D11 对照 cases/ 改自己的稿；记下 3 处差异与理由

可周末两天冲刺：D1–D2 + 只精读 RBAC/ABAC/08 + D9–D11。

3. 「我懂了」的验收标准

同时满足才算理论过关：

  1. 能讲：向非安全同事用 5 分钟讲清四元组、功能/数据分离、为何默认 RBAC
  2. 能画：主线+旁支地图；RBAC 三元关系
  3. 能选：给定一段业务描述，写出决策句式（见 05）
  4. 能写：独立完成 O1–O9，且 O6 消除「部门是否含下级」等歧义
  5. 能停：O7 明确不做项，O9 写清「什么信号才升级模型」

对照：06-outputs.md §验收标准。

4. 各章在理解链上的作用

文档 你获得的能力
01 定义问题，不跑题
02 知道需求「难在哪一阶段」
models/* 知道每个工具的理论边界
04 知道立项要问全哪些题
05 知道怎么选组合与档位
06 知道理论阶段交什么、怎样算做完
cases/* 知道「写好」长什么样
glossary 避免用词漂移

5. 三条学习纪律

  1. 先输出再对照案例——先看范例会变成抄写，检不出理解漏洞。
  2. 模型章必须做自测——只读不练，演进出不了手感。
  3. 理论与工程分册——本阶段禁止用「Spring 怎么配」代替模型理解。

6. 卡住时怎么跳

症状 回到
角色和部门分不清 01 §5 + glossary「角色 vs 部门」
不懂为何不要上 UCON 02 §5 + models/05
数据权限不知怎么写 01 §4 + 04-B + M 档案例 O6
决策树选不准档 05 + 三个 cases 封面对比
