08 · 对照、组合与选型误区

1. 学习目标

  • 能默写各模型「判定看什么」对照表
  • 能描述业务系统最常见的模型组合及其分工
  • 能识别至少五类选型误区
  • 能写出一段符合教材标准的「模型选型结论」

2. 总对照表

模型 判定主要看什么 一句话 主线/旁支
DAC 所有者如何授权 主人说了算 主线
MAC 安全标签与强制策略 系统强制 主线
RBAC 角色是否蕴含权限 你是什么角色 主线
ABAC 属性是否满足策略 条件满不满足 主线
UCON 授权+义务+条件（可持续/可变） 用的全过程 主线
ACL 客体上的名单 这东西允许谁 旁支
ReBAC 关系路径是否成立 你和它什么关系 旁支

3. 演进链上的「缺口传递」（复习）

DAC 灵活 → 缺口：扩散与弱全局策略
MAC 强制 → 缺口：过刚、不贴岗位
RBAC 岗位化 → 缺口：静态、难上下文、难实例分享
ABAC 动态细粒度 → 缺口：治理难；仍常偏请求时
UCON 使用全过程 → 缺口：完整落地重；概念易滥用

旁支补的是横切能力：

  • ACL：实例枚举
  • ReBAC：关系推导

4. 推荐组合（理论稳态）

层级 常见模型选择
功能权限（菜单/API/操作） RBAC
数据范围（本人/部门/租户） 轻量属性规则（ABAC 思想）
对象分享 / 协作 ACL 或 ReBAC
密级/强隔离红线 局部 MAC 思想
使用中吊销/义务/计量 局部 UCON 思想

口诀：

RBAC 打底，属性管范围，分享看 ACL/ReBAC，强制与持续按需加。

5. 选型误区（教材必记）

  1. 把演进线当实施顺序：新项目从 UCON「最新」开始 → 错
  2. 用角色表达数据范围：运营_华东_本人 角色爆炸 → 错
  3. 用 ACL 表达全站功能权 → 错
  4. 无策略治理上完整 ABAC → 错
  5. 把多租户过滤当成已经做了 MAC → 概念不清
  6. 部门树直接当角色树 → 功能/数据搅死
  7. 一个用户一个专属角色 → RBAC 名存实亡
  8. 用 UCON 名词包装普通登录鉴权 → 沟通通胀

6. 概念速辨（期末级）

易混对 一句话分开
DAC vs ACL 策略类别 vs 常见实现结构
角色 vs 部门 权限包 vs 组织归属/数据范围来源
ABAC vs 代码 if 可治理策略 vs 散落分支
ACL vs ReBAC 枚举谁 vs 推导谁
ABAC vs UCON 属性策略 vs 使用全过程（含义务/持续/可变）

7. 书面表达模板（可直接用于方案）

本项目以 RBAC 为功能权限主模型；
数据范围采用 本人/本部门/租户 属性规则（轻量 ABAC）；
文档类资源的分享采用 ACL（或 ReBAC，若存在深层嵌套成员继承）；
不引入全站 MAC；UCON 仅作为检查项：无会话中吊销/计量/强制义务需求。
对照演进线：需求主要落在 RBAC 阶段，局部触及 ABAC 思想与 ACL 旁支。

按项目实情替换下划线内容即可。更完整交付物见 ../06-outputs.md。

8. 综合自测

  1. 画出主线+旁支地图，并标注你司上一个系统大概落在哪。
  2. 给定需求：「运营可导出本部门订单；经理可看下级部门；单条订单可分享给协作人只读」。拆成模型分工。
  3. 说明为什么「最新模型」不是「更好模型」。

要点：2）导出/查看功能→RBAC；部门范围→属性规则；单条分享→ACL/ReBAC；3）匹配问题域与治理成本。
