01 · 自主访问控制（Discretionary Access Control / DAC）

1. 学习目标

读完本章，你应能：

  • 用自己的话定义 DAC，并指出「自主」自主在谁
  • 说明 DAC 与访问矩阵 / ACL / Capability 的关系
  • 列举 DAC 的典型优势与「权限扩散」类局限
  • 判断一个需求是不是「纯 DAC 思维」

2. 历史背景与发展

早期多用户操作系统（如 Unix 传统权限模型所体现的思想）需要回答：文件、进程等对象由谁控制访问。
一种自然答案是：对象有属主（owner），属主有权决定谁可以读/写/执行——这就是自主访问控制的直觉来源。

在经典访问控制理论中，DAC 常与 访问矩阵（Access Matrix） 一起出现：行是主体，列是客体，单元格是允许的操作。矩阵在实现上过稀、过大，于是演化出两种常见实现视角：

  • 按列存储 → ACL（每个客体一份名单）
  • 按行存储 → Capability（每个主体持有能力票证）

因此：DAC 首先是策略思想（谁有权改授权），ACL/Capability 是常见实现形态。不要把「DAC」和「ACL」当成同一个词。

DAC 要解决的是：灵活共享。
它很快暴露的问题是：授权可被属主（或被转授者）扩散出去，系统难以施加统一的全局安全策略——这直接推动了 MAC 的强化思路。

3. 核心理论

3.1 基本定义

DAC：客体的访问权限由该客体的属主（或属主委托的主体）自主决定；系统主要执行属主设定的规则，而不是用全局强制策略覆盖属主意愿。

3.2 核心概念

概念 含义
属主（Owner） 对客体拥有支配性授权权的主体
授权（Grant） 属主把某操作授给其他主体
转授（可能存在） 被授权者是否还能继续授给别人（策略可禁止或允许）
访问矩阵 Subject × Object → Rights 的抽象模型

3.3 判定如何发生

  1. 识别 Subject、Object、Action
  2. 查找该 Object 上由属主（或其授权链）设定的规则
  3. 若规则允许该 Subject 执行该 Action → 允许，否则拒绝

环境属性、全局密级通常不是 DAC 的一等公民（除非被实现额外叠加）。

3.4 最小例子

文档 D 的属主是 Alice。

  • Alice 授予 Bob「读」→ Bob 可读 D
  • Alice 未授予 Carol → Carol 不能读 D
  • 若允许转授，Bob 再授给 Carol「读」→ Carol 也能读（权限扩散开始出现）

4. 变体与扩展

  • 属主 + 属组 + 其他人（Unix rwx 思想）：粗粒度 DAC
  • 细粒度 ACL：每用户/每组一条 ACE（Access Control Entry）
  • 可转授 vs 不可转授：是否允许 grant-propagate
  • 与审计、默认权限（umask 类思想）结合：仍属 DAC 家族的工程化

5. 优势

  • 符合人类直觉：谁创建谁管理，协作成本低
  • 灵活：临时分享、撤销（在属主控制下）自然
  • 实现路径成熟：操作系统与内容系统大量验证

6. 不足与局限

  1. 权限扩散（Trojan / 转授风险）：恶意或疏忽可使权限流向不可控主体
  2. 全局策略弱：难以强制「所有机密文件不得分享给外包」这类组织级规则
  3. 审计与治理难：授权决策分散在无数属主手中
  4. 不擅长岗位化管理：企业要的是「运营岗能做什么」，不是「每个文件找主人」
  5. 客体海量时：纯属主模式运维负担高（常要引入管理员代管，反而靠近中心化）

7. 在演进链中的位置

  • 相对「无模型」：给出了可分析的授权主体（属主）
  • 留给 MAC 的缺口：缺强制、缺防扩散的系统级保证
  • 与后代：RBAC/ABAC 并不消灭 DAC；分享场景仍大量使用 DAC/ACL 思维

8. 适用与不适用

更适用 更不适用
个人网盘、文档协作分享 作为企业后台唯一权限模型
属主清晰的对象级授权 强合规、强防泄露、统一岗位授权
OS / 文件系统经典场景 需要「角色—权限」集中治理的 ERP

9. 概念辨析

概念 辨析
DAC vs ACL DAC 是策略类别；ACL 是（常用于实现 DAC 的）数据结构视角
DAC vs RBAC DAC 问「主人给没给」；RBAC 问「你有没有这个角色」
属主 vs 管理员 管理员代管不等于变成 MAC；关键仍看「最终策略是否可由属主左右」

10. 小结与自测

小结

DAC 用「属主自主授权」换取灵活性，代价是扩散风险与弱全局治理。它是经典双雄之一，也是今日「分享」需求的理论祖先。

自测

  1. 为什么说 ACL 不等于 DAC？
  2. 举一个「权限扩散」的具体故事（三步即可）。
  3. 若公司要求「任何属主都不能把机密文档分享出公司」，这还是纯 DAC 吗？为什么？

要点：1）策略 vs 实现；2）A→B→C 转授；3）已出现强制约束，偏向 MAC 或策略覆盖。
